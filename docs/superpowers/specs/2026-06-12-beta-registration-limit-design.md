# 10 人内测注册限制设计

## 目标

Studio Aruo 第一批内测最多开放 10 个账号。现有账号计入名额；达到上限后停止新注册，但已注册用户仍可正常登录和使用。

## 范围

本功能包含：

- 后端以数据库中的全部用户数量计算已用名额。
- 提供公开注册状态接口。
- 注册页显示剩余名额。
- 名额用完后保留注册页，但隐藏表单并显示“首批内测名额已满”。
- 注册接口在达到上限后拒绝新账号。
- 防止多个请求同时越过最后一个名额。

本功能不包含：

- 付费账号开通。
- 邀请码、候补名单或管理员扩容。
- 删除账号后永久占用名额。
- 对现有账号设置到期时间。

## 名额规则

- 默认上限为 10。
- 所有 `users` 表记录都计入名额，不区分创建时间。
- 已注册的内测账号永久保留使用权限。
- 如果账号被真正删除，释放一个名额。
- 上限由服务端环境变量 `BETA_USER_LIMIT` 控制，未配置时使用 10。

## 数据库并发控制

仅在注册接口中先查询数量再插入会产生竞态：两个请求可能同时看到剩余一个名额。注册操作必须在同一数据库事务中取得事务级 advisory lock，然后依次执行：

1. 获取固定的注册锁。
2. 查询 `users` 总数。
3. 达到上限则返回 `registration_full`。
4. 未达到上限则插入新用户。
5. 提交事务并释放锁。

用户名唯一约束继续作为重复账号的最终保护。

## 接口

新增公开接口：

`GET /api/registration-status`

返回：

```json
{
  "limit": 10,
  "registered": 4,
  "remaining": 6,
  "open": true
}
```

当名额已满：

```json
{
  "limit": 10,
  "registered": 10,
  "remaining": 0,
  "open": false
}
```

注册接口 `POST /api/auth/register` 在满额时返回 HTTP 409：

```json
{
  "error": "registration_full"
}
```

## 注册页面

注册页面加载时请求注册状态：

- 有剩余名额：显示“首批内测剩余 X 个名额”和现有表单。
- 名额已满：显示“首批内测名额已满”，隐藏所有注册输入和提交按钮，保留“已有账号？去登录”。
- 状态接口暂时失败：仍显示表单，但最终是否允许注册由后端决定；提交失败时显示服务端错误。
- 用户填写表单期间名额被其他人占满：提交后显示“首批内测名额刚刚用完”，不清空用户已填写内容。

## 安全与错误处理

- 客户端剩余名额仅用于展示，不能作为安全判断。
- 服务端不接受客户端传入的名额或用户数量。
- `BETA_USER_LIMIT` 小于 1 或不是整数时回退为 10。
- 数据库失败返回通用服务错误，不将 SQL 或连接信息暴露给客户端。

## 测试与验收

自动化测试覆盖：

- 默认上限和环境变量解析。
- 0、9、10 个账号时的状态计算。
- 满额注册返回 `registration_full`。
- 并发注册不能使账号数超过上限。
- 注册页面根据 `open` 显示表单或满额提示。
- 注册页面识别 `registration_full` 错误。

人工验收：

1. 数据库账号数小于 10 时，注册页显示正确剩余名额。
2. 创建第 10 个账号成功。
3. 第 11 个账号无法注册。
4. 直接调用注册接口也不能绕过限制。
5. 原有账号仍可登录并进入工作台。
